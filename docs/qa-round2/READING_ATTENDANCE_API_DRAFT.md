# 출석 서버 저장 API 초안 — 미구현·미배포

현재 읽기 로그와 읽기 연속 기록은 기기별 저장소다. 기존 웹/폰/재설치 데이터를 자동 병합하지 않는다.

- `PUT /api/learning/reads/{newsId}`: JWT의 사용자 ID만 사용. 서버 시각의 Asia/Seoul 날짜로 한 기사당 하루 1회 upsert. body의 userId/기기 시각을 신뢰하지 않는다. 실제 존재하는 기사·접근 가능 여부 확인, 요청 크기·호출 제한 적용.
- `GET /api/learning/reads?from=YYYY-MM-DD&to=YYYY-MM-DD`: 본인 로그만, 최대 366일. 날짜별 고유 기사 ID와 읽은 수, 3개 읽기 달성, KST 주간 출석과 연속 달성 반환.
- 동일 기기·다른 기기의 중복 PUT은 PK로 합쳐진다. 로그인 이후 서버 로그가 기준이며, 오프라인 요청은 재시도 가능한 큐로 보관하고 서버가 확인한 응답만 확정한다.
- 기존 localStorage 로그는 검증되지 않은 클라이언트 자료다. 자동 승격/백필 금지. 가져오기 기능은 별도 사용자 결정과 데이터 검증 후 설계한다.
- 삭제 계정은 cascade로 지운다. 조회는 JWT 소유권을 항상 적용하고 과거 데이터 수정 API는 제공하지 않는다.
- 검증 계획: 두 기기 중복 읽기·다른 사용자 격리·재설치 복원·KST 자정·주 경계·오프라인 중복·미래 날짜 거절·기사 삭제·계정 삭제.

운영 DB에는 적용하지 않았다. 아래 SQL은 Flyway 바깥의 검토용 초안이며, 이번 프런트는 기존 로컬 저장을 유지하고 “이 기기 기준”으로 표시한다.
