# 퀴즈에서 다시 볼 개념·추천으로 이어지는 표시 정책

BKT 업데이트·망각 가중·출제 선택·수준 제안·추천 가중치는 유지합니다. 표시할 개념과 추천 이유만 바꿉니다.

- 답변 message는 정답 ‘정답이에요!’, 오답 ‘아쉬워요’입니다. 기존 definition은 정답 보기(증가/감소/기사 밖 사실 문항 포함)와 하위 호환을 유지합니다. 새 termDefinition은 개념의 뜻입니다. 프런트는 정답 보기를 강조하되 결과에는 개념 뜻만 표시합니다.
- reviews는 개념별 마지막 응답만 보고 마지막 오답 또는 effectivePKnown < 0.6인 개념을 낮은 숙련도 순·동률 용어순으로 최대 10개 반환합니다. 고숙련 정답은 제외합니다.
- 추천 가중치와 30일 범위, 기존 유사도/임베딩 선택은 그대로입니다. 동일 근거 기사에 여러 활동이 있으면 오답 → 메모 → 판단 순으로 이유를 표시하며 오답 용어는 가장 최근 것을 사용합니다. 읽기만 있으면 읽은 기사 제목으로 이유를 표시합니다.
- 이유: ‘금리’ 퀴즈를 틀린 기사와 비슷해요 / 메모한 ‘제목 앞 15자…’와 비슷해요 / 판단한 ‘제목 앞 15자…’와 비슷해요. 원래 제목이 15자 이하이면 … 없이 표시합니다.
- 근거 기사를 찾지 못한 RULE_RECENT 항목은 추천 목록에서 제외합니다. 빈 응답의 basis는 기존 RULE_RECENT로 유지합니다.
- GET /api/learning/news/{id}?level=beginner&term=금리: 복습 버튼에서 용어를 명시하면 그 기사의 해당 용어 퀴즈를 엽니다. 기사에 없는 용어/출제 불가 용어는 400입니다. term을 보내지 않으면 기존 BKT 선택을 유지합니다. 채점·학습 업데이트는 기존 answers API를 사용합니다.

## 검증

./gradlew test 통과. 별도 로컬 PostgreSQL의 prod 마이그레이션/통합 4개 통과. 단위 테스트는 오답·저숙련 포함, 0.6 경계 고숙련 정답 제외, 개념별 최신 응답, 최대 10개, 정확한 복습 용어 선택/검증, 추천 이유 3종과 cold-start 제외를 확인합니다. 실제 PostgreSQL에서 2.7 가중치를 유지한 채 오답/메모/판단 이유가 바뀌는 것도 확인했습니다. 통합 테스트 데이터는 별도 테스트 DB에만 생성하고 롤백합니다.

실제 로컬 시연 DB는 read-only SELECT만 실행했습니다.

| 계정 | 개념별 최신 응답 | 새 조건 포함 | 고숙련 정답 제외 | 포함 개념 |
|---|---:|---:|---:|---|
| 민지 | 8 | 3 | 5 | 기준금리·환율·금리 |
| 준호 | 8 | 2 | 6 | 수급·밸류에이션 |

현재 준호 시연 DB에는 오답이 남아 있으므로 이 두 개념은 계속 포함됩니다. 모든 마지막 답이 정답이고 effectivePKnown ≥ 0.6인 경우 빈 목록이 되는 것은 별도 테스트로 확인했습니다. 기존 DB·환경 파일·마이그레이션·외부 호출 상한은 변경하지 않았고 유료 LLM 호출은 하지 않았습니다.
