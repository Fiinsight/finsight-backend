# 맞춤형 학습 발표 대본

이 기록은 **시연용 가상 사용 이력**입니다. 뉴스는 기존 DB 기사, 퀴즈는 실제 생성 규칙을 사용합니다. 숙련도는 정답·오답 이력을 실제 BKT 함수에 넣어 계산합니다. 수익률은 만들지 않습니다. 기능이 구현되어 있어도 데이터나 로컬 모델이 준비되지 않았다면 그 장면은 준비 중이라고 설명합니다.

## 실행과 비교

백엔드 저장소에서 실행합니다. Java 21, Python 3, PostgreSQL `psql`이 필요합니다. SQL + Python 래퍼 방식이며 Spring 서버를 새로 띄우지 않습니다. 따라서 수집·피드백 스케줄러나 전역 용어 시더가 실행되지 않습니다.

```sh
scripts/seed_demo_personas/run.sh                       # 기본 dry-run: 생성/삭제 예정 건수
scripts/seed_demo_personas/run.sh --apply --report /tmp/demo-personas.json
python3 scripts/seed_demo_personas/verify.py --news-id 1 --base-url http://localhost:8080
```

DB 연결은 기존 백엔드 `.env`에서, 비밀번호는 상위 Finsight 디렉터리의 `.env.demo.local`의 `DEMO_PASSWORD`에서 읽습니다. 두 파일 모두 출력·생성·수정·커밋하지 않습니다. 원격 또는 `finsight`/`finsight_demo` 외 DB는 거부합니다. 세 이메일의 LOCAL 계정만 잠그고 한 트랜잭션에서 기록을 지웠다가 다시 넣습니다. 사용자 ID는 유지합니다. 실패하면 전체 롤백합니다. 신규 마이그레이션은 없습니다.

| 계정 | 이메일 | 수준 | 어려운 점 | 목표 |
|---|---|---|---|---|
| 민지 | demo-beginner@finsight.test | 초보자 | 용어 | 뉴스 하나 읽기 |
| 준호 | demo-investor@finsight.test | 분석 | 판단 근거 | 투자 판단 돌아보기 |
| 새 사용자 | demo-new@finsight.test | 온보딩 전 | 미정 | 미정 |

`직접 투자하고 있어요` 답변은 기존 매핑에 따라 **분석** 수준입니다. 세 계정은 같은 시연 비밀번호를 사용하며 발표에 비밀번호나 토큰을 띄우지 않습니다. 새 사용자는 서버 이력이 비어 있으므로 별도 브라우저 프로필에서 온보딩을 시작합니다.

## 1. 문제 제기 — 10초

- **화면:** 같은 기사 제목 한 개.
- **누를 것:** 기사 상세 진입.
- **멘트:** “같은 뉴스라도 초보자는 용어 설명이, 경험자는 판단의 근거가 필요해요. 핀사이트는 설명과 학습 순서를 사용자에 맞춥니다.”
- **질문/답:** “추천 기사도 달라지나요?” → “공통 핵심 뉴스는 같습니다. 읽는 수준과 학습 순서가 먼저 달라지고, 추가 추천은 행동 이력을 참고합니다.”

- **멘트:** “답변을 통해 읽기 수준, 관심사, 어려운 점과 오늘 목표를 정합니다. 이후 퀴즈 결과가 쌓이면 숙련도를 따로 추정합니다.”
- **질문/답:** “온보딩만으로 실력을 아나요?” → “초기 설정일 뿐입니다. 실제 실력이라고 단정하지 않고 답변 기록으로 추정을 갱신합니다.”

## 3. 민지와 준호 학습 탭 비교

- **화면:** 서로 다른 브라우저에 민지·준호 학습 탭을 나란히 표시.
- **누를 것:** 민지 ‘오늘의 용어 3개’ → 복습 칩 → 두 계정 ‘내 개념 숙련도’.
- **멘트:** “민지는 금리·환율·기준금리 복습이 먼저 나오고, 준호는 밸류에이션과 수급을 다시 확인합니다. 같은 기능이어도 복습 우선순위와 설명 수준이 달라집니다.”
- **질문/답:** “약한 분야가 왜 없나요?” → “실제 종가로 채점한 판단이 분야별 5건 이상일 때만 표시합니다. 데이터가 부족하면 억지로 분야를 만들지 않습니다.”
- **준비 조건:** 준호의 ‘다시 살펴볼 분야’는 정상 저장 종가가 부족한 현재 DB에서 표시되지 않습니다. 그 영역이 있는 것처럼 설명하지 말고 숙련도 비교로 진행합니다.

## 4. 같은 기사, 다른 설명과 퀴즈

- **화면:** 두 계정에서 같은 기사(검증 스크립트에서 유형 차이가 확인된 ID)를 열기.
- **누를 것:** 쉽게읽기 → 퀴즈.
- **멘트:** “민지는 용어의 기본 의미를, 준호는 기사에 나온 사실을 구분하는 문제를 풉니다. 저장된 리라이팅이 없으면 발췌라는 안내도 함께 표시합니다.”
- **질문/답:** “실시간으로 유료 AI를 호출하나요?” → “이 시연에서는 호출하지 않습니다. 기존 저장 설명과 무료 규칙 문제를 사용합니다.”
- **주의:** 어떤 기사에서는 분석 문제의 근거 문장이 부족해 초보 문제로 대체됩니다. 사전에 API 비교 결과를 확인합니다.

## 5. 민지 승급 제안 — 실제 변화

- **화면:** 민지 학습 탭, 제안 없음 → 퀴즈 → 학습 탭의 ‘일반용으로 읽어볼까요?’.
- **누를 것:** 현재 출제되는 금융 개념 퀴즈를 풀고 학습 탭의 제안 여부를 확인합니다. AI·반도체는 TOPIC으로 분류되어 더 이상 승급용 퀴즈로 출제되지 않습니다. 기존 시드의 `promotionQuizzes`(7/55)는 사용하지 말고, 리허설에서 CONCEPT 또는 초보자 MARKET 문항으로 준비하세요.
- **멘트:** “현재 수준에서 숙련도 기준을 넘는 서로 다른 학습 개념이 다섯 개가 되면 다음 수준을 제안합니다. 수준은 자동으로 바꾸지 않고 사용자가 선택합니다.”
- **질문/답:** “몇 문제면 승급하나요?” → “이전 답변에 따라 달라집니다. 확률 85% 이상인 서로 다른 개념이 다섯 개 필요합니다. TOPIC 기록을 보존한 현재 시드에서는 두 문항만으로 제안이 뜨는 장면을 보장하지 않습니다.”
- **누를 것(선택):** 제안 버튼을 눌러 일반 수준으로 변경. 최종 리허설 후 다시 시드하면 초보자 상태로 돌아갑니다.

## 6. 준호 판단 → 근거 피드백 → 차트

- **화면:** 준호의 정상 다음 거래일 판단 상세 → 근거 항목 → 해당 종목 차트의 급등락 도슨트.
- **누를 것:** 결과가 나온 판단 → 기사 → 종목 차트 → 급등락 지점.
- **멘트:** “내 판단 근거, 기사 내용, 실제 비교 종가를 나눠 확인합니다. 뉴스와 가격이 같은 시점에 움직였더라도 확정된 원인으로 말하지 않습니다.”
- **질문/답:** “뉴스 때문에 주가가 움직였다는 뜻인가요?” → “아닙니다. 관련성에 대한 가능한 설명이며 실제 원인은 여러 요인이 겹칠 수 있습니다.”
- **현재 대체 장면:** 준호에 넣을 수 있는 정상 종가 자료가 없어 판단은 0건입니다. 이를 감추지 말고 준호로 기사·차트 도슨트를 열어 구조를 보여줍니다. 판단 상세 장면은 **검증된 시연 계정 판단 데이터가 준비된 뒤** 녹화합니다. 일반 계정의 판단을 복사하거나 다른 종목의 종가를 붙이지 않습니다.

## 7. 기술 설명 — 30초

- **화면:** 숙련도 그래프와 설명/추천의 출처 표시.
- **누를 것:** 숙련도 근거 문구, 추천 근거 확인.
- **멘트:** “초기 설정은 규칙으로 정하고, 정답·오답은 베이지안 지식 추적 확률 모델로 반영합니다. 감성과 유사도는 공개 사전학습 모델을 로컬에서 활용할 수 있고 무거운 계산은 배치로 저장합니다. 모델이 없는 환경에서는 무료 규칙으로 대체합니다.”
- **질문/답:** “딥러닝을 직접 학습했나요?” → “직접 학습한 대규모 모델은 없습니다. 확률 모델과 공개 사전학습 모델을 활용했습니다. 실제 모델 평가 수치는 사람이 라벨링한 평가를 마친 뒤 제시합니다.”
- **현재 준비 상태:** 로컬 모델 설치·임베딩·감성 배치를 아직 실행하지 않았다면 모델 결과라고 소개하지 않습니다. 현재 시연의 BKT 계산은 실제 적용되며 나머지는 규칙 대체일 수 있습니다.

## 발표 기기 읽기 기록 주입

웹 발표용입니다. `.env`나 토큰을 붙여넣지 않습니다. 시드 결과의 `newsIds` 중 3개를 `ids`에 넣고, **해당 계정으로 로그인한 발표 앱 탭**의 브라우저 콘솔에서 실행합니다. 서버 DB는 변경하지 않습니다. 현재 기사 예시는 1·2·3이며 시드가 새 기사만 선택하게 되면 결과 파일의 ID로 바꿉니다.

```js
(() => {
  const session = JSON.parse(localStorage.getItem('finsight.auth') || 'null');
  const allowed = ['demo-beginner@finsight.test', 'demo-investor@finsight.test', 'demo-new@finsight.test'];
  if (!session || !allowed.includes(session.email) || !Number.isSafeInteger(session.userId)) throw new Error('시연 계정으로 로그인해 주세요.');
  const ids = [1, 2, 3]; // 시드 JSON의 실제 newsIds로 교체
  const days = session.email.startsWith('demo-beginner@') ? 5 : 10;
  const log = {};
  const today = new Intl.DateTimeFormat('en-CA', { timeZone: 'Asia/Seoul', year: 'numeric', month: '2-digit', day: '2-digit' }).format(new Date());
  if (!session.email.startsWith('demo-new@')) {
    for (let i = 0; i < days; i++) {
      const day = new Date(`${today}T12:00:00+09:00`);
      day.setUTCDate(day.getUTCDate() - i);
      const key = new Intl.DateTimeFormat('en-CA', { timeZone: 'Asia/Seoul', year: 'numeric', month: '2-digit', day: '2-digit' }).format(day);
      log[key] = [...new Set(ids)];
    }
  }
  localStorage.setItem(`finsight.learning.reading.v1:${session.userId}`, JSON.stringify(log));
  localStorage.removeItem(`finsight.learning.judgement-views.v1:${session.userId}`);
  location.reload();
})();
```

읽기 기록은 기기별 저장이므로 다른 브라우저에서도 별도로 실행합니다. ‘오늘 읽은 기사’와 읽기 목표 달성이 서버 시드만으로 만들어졌다고 설명하지 않습니다. API 검증은 기본적으로 서버 기록만 비교합니다.

## 발표 전날 체크리스트

- [ ] frontend / backend / AI 서버 3개 기동. 유료 호출 플래그는 계속 끔.
- [ ] 시드 dry-run → 생성/삭제 예정·부족 데이터 확인 → `--apply` 재실행.
- [ ] 같은 기사 API 비교표에서 기본 수준·복습·퀴즈 유형을 확인.
- [ ] 부족한 정상 종가가 있으면 판단/약한 분야 장면을 준비 중으로 표시하거나 대체 장면 사용.
- [ ] 브라우저 두 개(저장소가 분리된 프로필)에 민지·준호 로그인, 읽기 스니펫 실행.
- [ ] 새 사용자용 별도 브라우저, 온보딩 초기 상태 확인.
- [ ] AI·반도체 `promotionQuizzes`는 사용하지 않고, 실제 금융 개념 문항과 현재 승급 조건을 리허설에서 확인. 기존 기록 재생성은 별도 허용 후 실행.
- [ ] 녹화본 백업. 비밀번호·토큰·환경 파일이 녹화되지 않는지 확인.
