# 시연 성향 3계정 시드

전체 실행·발표 순서는 `docs/demo-script.md`를 참고하세요.

- `run.sh` 기본은 DB 읽기만 하는 dry-run입니다. `--apply`만 세 시연 계정을 갱신합니다.
- 계정은 정확히 `demo-beginner`, `demo-investor`, `demo-new`의 `@finsight.test` LOCAL 계정입니다.
- `.env`는 연결 정보, 상위 폴더 `.env.demo.local`의 `DEMO_PASSWORD`는 비밀번호를 읽는 데만 사용합니다. 파일 생성·출력·수정이 없습니다.
- 기존 `seed_demo.py`와 다른 시드입니다. 기존 스크립트의 BCrypt 해시 함수만 재사용하고 가상 수익률·환경 파일 생성은 호출하지 않습니다.
- 실제 `LearningService` 문제 생성, `KnowledgeTracing` 계산, `KoreanTradingCalendar` 검증을 Java 21 오프라인 명령으로 재사용합니다. 정답 정보는 앱 API에 추가하지 않습니다.
- 14일 내 같은 `(user, news, term)`을 중복 저장하지 않습니다. learning_progress가 문항별 최종 답만 저장하는 현행 구조에 맞추어 서로 다른 실제 문항을 사용합니다.
- 저장된 정상 판단 종가를 읽어 가격 자료로 확인합니다. 현재 제목/본문 매핑과 다르거나 가상 결과이면 제외합니다. 실제 일봉 저장 테이블이 없는 현재 구조에서는 자료가 부족할 수 있습니다.
- 숙련도 테이블이 없는 구형 DB는 저장을 생략하고 알려드립니다. 마이그레이션이나 백필을 자동 실행하지 않습니다.
- 계정별 고정 규칙을 채우지 못하면 부족 건수를 출력합니다. 계획에 없는 기사나 수익률을 만들지 않습니다.
- `--report /tmp/demo-personas.json` 결과는 시연 사용자 ID, 뉴스 ID, 숙련도 및 승급 시연 문항만 포함합니다. 비밀번호·토큰은 없습니다.
- `verify.py --news-id ID`는 수준을 명시하지 않고 기본 설정을 검증합니다. 부족한 약한 분야/퀴즈 차이 등은 표와 제한 설명, 종료 코드 2로 보고합니다. API 자체 실패는 비밀 없이 종료합니다.
- 테스트: `./gradlew test`에 Python 범위 제한 테스트도 포함되어 있습니다. CI 모델 다운로드·유료 호출·실제 DB 시드는 없습니다.
