# 로컬 시연 데이터

목적지는 loopback(127.0.0.1 / ::1 / localhost), 포트5432의 기존 개발 DB `finsight`만 허용합니다. 연결 후 서버 주소와 DB명을 다시 확인합니다. 별도 DB 생성·스키마 변경·기사 수집·외부 API 호출은 없습니다. 2026-10-06 날짜 검증 자체 테스트 통과 후 사용자 승인 범위에서 실행했습니다. 계정1·판단3·메모3·퀴즈3건을 확인했습니다.

## 생성 내용

- 계정: `finsight-demo@finsight.test`, 표시 이름 `시연용 가상 학습 계정`, LOCAL 로그인.
- 기존 실제 기사 중 사전 용어가 포함되고 각 판단 날짜 이전(같은 날 포함)에 발행된 서로 다른 기사3건에 연결합니다. SYNTHETIC 출처·example.invalid URL·짧거나 없는 본문은 제외합니다. 부족하면 삽입하지 않습니다. 기사와 용어 사전, 다른 사용자 데이터는 수정하지 않습니다.
- 판단3건: 1일 전 상승/상승(+1.2%), 3일 전 상승/하락(-0.8%), 14일 전 중립/중립(+0.2%). 결과와 피드백에는 `[시연용 가상 결과]`를 명시합니다. 실제 수익률이 아닙니다.
- 기사 메모3건, 퀴즈 기록3건(정답1·오답2). 판단 날짜의23:59:59(KST)에 기록하고, 기사 발행시각이 반드시 그 시각보다 이른 경우만 선택합니다. 메모·퀴즈도 같은 날짜입니다. 2026-10-06 기준 [9/23~9/30) 구간을 비워 빈 주 건너뛰기를 확인합니다.
- 온보딩: normal / short / routine. 백엔드 UserProfileService가 사용하는 값이며 프론트는 short→micro, routine→reflection으로 읽습니다.

## 비밀번호와 재실행

QA 계정의 비밀번호를 읽거나 복사하지 않습니다. 최초 실행 때 secrets로 새 비밀번호를 만들고, 이미 설치된 Spring Security BCrypt로 해시합니다. 원문은 프로젝트 루트의 gitignored `.env.demo.local`에만 0600 권한으로 저장하며 화면·로그에 출력하지 않습니다. DB에는 해시만 저장합니다.

표시 이름·이메일·LOCAL 유형이 일치하는 시연 계정이 이미 있으면 **아무 변경 없이 종료**합니다. 비밀번호 파일도 쓰지 않습니다. 이메일이 다른 사용자 계정과 충돌하면 거부합니다.

비밀번호 파일은 DB 삽입 전에 만듭니다. SQL 실패 시 삽입은 전부 롤백되고 파일은 보존됩니다. 승인받은 재실행은 안전한 기존 시연 비밀번호 파일을 재사용합니다. 다른 형식이나 공개 권한의 파일은 덮어쓰지 않고 거부합니다.

## 승인 후 실행 명령

```sh
python3 scripts/seed_demo.py --confirm-local-demo
```

PostgreSQL 인증은 기존 로컬 인증 환경을 사용합니다. DB 암호를 인자로 전달하거나 출력하지 않습니다.

## 정리 (별도 승인 후에만 실행)

```sh
python3 scripts/seed_demo.py --cleanup --confirm-local-demo
```

이메일·표시 이름·LOCAL 유형을 확인한 시연 계정 id에 연결된 learning_progress, article_note, daily_note, judgement만 삭제한 뒤 그 계정을 삭제합니다. 이후 해당 시연 계정으로 추가한 기록도 포함됩니다. 기존 기사, 용어, 다른 사용자 데이터는 삭제하지 않습니다. 비밀번호 파일은 보존합니다. 계정이 없으면 아무 변경 없이 종료합니다. 예상하지 못한 외래 키가 있으면 전체 트랜잭션이 롤백됩니다.

## SQL 요약

| 테이블 | 생성 | 정리 |
|---|---:|---|
| app_user | 1행 | 확인된 시연 계정1행 |
| judgement | 3행 | 해당 계정 id의 행만 |
| article_note | 3행 | 해당 계정 id의 행만 |
| learning_progress | 3행 | 해당 계정 id의 행만 |
| daily_note | 0행 | 해당 계정 id의 행만 |
| news / term / 기타 사용자 | 0행, 수정 없음 | 삭제 없음 |

삽입·정리는 각각 하나의 트랜잭션입니다. 자체 테스트는 실제 DB 및 비밀번호 파일에 접근하지 않으며 생성 행 수, 1·3·14일 전 날짜와 발행 시각보다 엄격히 늦은 판단 시각, 빈 주 구간, 목적지 제한, BCrypt, 재실행 무변경, id 한정 정리를 확인합니다.

```sh
python3 scripts/seed_demo.py --self-test
```
